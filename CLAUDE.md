# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Zero-build static web app that generates Tailwind-style 11-step OKLCH color palettes from a single seed color. Produces C# output for MonorailCSS's `ThemeDefaults.cs` and Tailwind v4 `@theme { }` blocks. Deployed to GitHub Pages at https://monorailcss.github.io/color-scheme-gen/.

## Commands

- **Serve locally** (ES modules require HTTP): `python -m http.server 8000` or `npx serve .`, then open http://localhost:8000.
- **Rebuild generated data** after editing `benjamin-moore.json`: `node scripts/build-paint-data.mjs` — regenerates `color-names.js`.
- **Deploy**: push to `main`. `.github/workflows/deploy.yml` runs the build step and publishes to Pages; the workflow also rewrites `<base href="./" />` in `index.html` to `/color-scheme-gen/` so subpath routing works.

No tests, linter, or bundler — it's hand-written HTML + ES modules.

## Architecture

Key invariants for palette generation:

- **OKLab L is stored internally as 0..1.** The curve tables in `palette.js` are already in 0..1. When formatting for output, `formatOklch` (C#, uses percent) and `formatOklchTheme` (Tailwind, uses decimal) diverge — don't unify them.
- **Lightness curves are the spine.** `palette.js` exports four fixed L curves (foreground/neutral × normal/high-contrast). The anchor step does *not* tilt them; it only sets the pivot for chroma scaling and hue drift.
- **Chroma logic differs by kind.** Foreground chroma is *relative* to the anchor (peak chroma = seed.C / fraction[anchorIndex]). Neutral chroma is *absolute* with an intensity multiplier, and the indices 6..10 (steps 600–950) blend between a tapered tail and a "held-high" tail via `darkChromaRetention`.
- **Gamut mapping is hue-preserving.** `color.js::gamutMapOklch` binary-searches the largest in-gamut chroma at the same (L, H). The OKLCH values emitted to C#/Tailwind are **not** gamut-mapped (matches Tailwind 4.x behavior) — only the hex preview is. Out-of-gamut steps get a warning badge with an explanatory tooltip.

## Data pipeline for color-name suggestions

`benjamin-moore.json` → `scripts/build-paint-data.mjs` → `color-names.js` (committed, regenerated by CI).

Two things the build script does that must be preserved:
1. **Dedup by name** so identical suggestions don't shadow each other.
2. **Histogram-equalize the L values.** The source paint set is top-heavy in whites (~60% above L=0.7, nothing below L=0.3), so raw OKLab distance collapses every dark seed onto ~5 names. We rank-remap L to a uniform [0, 1] before emitting. The stored L is intentionally *not* the real color's L — the data is a name pool, not a color accuracy table. If you change the source data or rebuild logic, keep this equalization or dark-seed variety will regress.

At runtime (`app.js::nearestName`), matching is plain Euclidean distance in (L', a, b) where L' is the equalized value. The name input is auto-filled on seed change only while it's empty *or* equals the last auto-filled name (`state.lastAutoName`) — user edits lock auto-fill off.

## Tailwind reference palettes

`tailwind-palettes.js` contains OKLCH values for 22 Tailwind v4 colors, transcribed from Tailwind source. Used by the "Compare to Tailwind" dropdown and the "Load into controls" button (reads the selected palette's 500 step, auto-picks foreground/neutral kind based on chroma threshold 0.05).

## Deploy subpath

`index.html` ships with `<base href="./" />`. The GitHub Actions workflow (`.github/workflows/deploy.yml`) rewrites this to `/<repo-name>/` using `${GITHUB_REPOSITORY#*/}`, so renaming the repo will Just Work. Any new absolute-rooted asset paths added later must respect the base, or the workflow's sed replacement needs updating.
